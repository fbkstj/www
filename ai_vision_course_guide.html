01 步驟一至步驟五：初學闖關式保證成功提示語

針對初學者設計之依序操作步驟，附帶【任務目標】與【過關成功的樣子】。

【步驟一】相機硬體與環境體檢

任務目標：確認 USB 鏡頭有插好，檢查電腦是否已具備基礎 Python 環境。

【步驟一】請幫我檢查目前 Windows 系統上是否有連接 USB 網路攝影機（如 Logitech C270），並列出攝影機的名稱與運作狀態，以及檢查 Python 環境中是否已安裝 opencv-python 與 ultralytics。請一律使用繁體中文回覆。
過關成功的樣子：AI 回報「有偵測到攝影機，狀態 OK，OpenCV 已就緒」，即可進行步驟二。
【步驟二】下載輕量化 AI 模型核心

任務目標：下載 5.4MB 的超輕量 AI 模型，確保一般文書筆電的 CPU 也能跑出 30 FPS。

【步驟二】請幫我安裝 ultralytics 庫，並在專案目錄下載最新輕量化的 YOLO11 Nano 模型（yolo11n.pt、yolo11n-pose.pt、yolo11n-seg.pt），完成後測試模型能否在 CPU 上正常進行推論。
過關成功的樣子：AI 回報「模型下載完成，CPU 測試推論通過！」，即可進行步驟三。
【步驟三】建立高穩定實時辨識程式

任務目標：生成相容性最好、不卡頓的 OpenCV 視窗程式，支援「物件、骨架、去背」熱鍵切換。

【步驟三】請在專案目錄中建立一個名為 webcam_ai_detect.py 的 Python 程式，規格如下：
1. 使用 OpenCV 開啟預設攝影機（設定解析度為 1280x720，FOURCC 設為 MJPG）。
2. 使用 YOLO11 Nano 模型進行實時推論，並在畫面上方顯示即時 FPS。
3. 支援鍵盤熱鍵即時切換：
   - 按 '1'：切換為通用物件偵測 (yolo11n.pt)
   - 按 '2'：切換為人體姿態骨架 (yolo11n-pose.pt)
   - 按 '3'：切換為實例影像分割去背 (yolo11n-seg.pt)
   - 按 'q' 或 ESC：安全關閉離開
4. 標籤名稱請對照 COCO 80 種常見類別顯示標準繁體中文。
過關成功的樣子：AI 回報已建立 webcam_ai_detect.py 且語法編譯通過，即可進行步驟四。
【步驟四】建立防閃退一鍵啟動腳本

任務目標：建立一個在任何 Windows 電腦（包含 Google 雲端虛擬硬碟）雙擊都不會閃退的啟動檔。

【步驟四】請在專案目錄建立一個 Windows 一鍵啟動批次檔 run_ai.bat：
1. 必須使用 pushd "%~dp0" 處理路徑，確保支援 Google 雲端硬碟等虛擬目錄。
2. 批次檔內容必須使用 100% 純 ASCII 英文（不得包含中文字元，避免 Windows Big5 編碼衝突導致閃退）。
3. 執行 python webcam_ai_detect.py，並在結尾加上 pause，確保出錯時視窗不會瞬間關閉。
過關成功的樣子：AI 回報已成功建立 run_ai.bat，即可進行最後一步。
【步驟五】啟動視窗與即時功能體驗

任務目標：在電腦實體螢幕上看見即時動態畫面，體驗熱鍵與物品辨識。

【步驟五】請告訴我如何正確在螢幕上看到即時攝影機視窗？請提供滑鼠雙擊啟動與終端機啟動這兩種方法，並說明啟動後如何用手勢與日常物品進行功能測試。
過關成功的樣子：學生直接雙擊 run_ai.bat，螢幕立刻彈出彩色畫面，拿起手機會被框出，按鍵盤 2 身上連起彩色人體骨架！🎉

🔹 下次開新對話接關提示語（3秒找回記憶）

隔天開啟新對話時，第一句直接貼上：

請先讀取專案目錄下的 PROJECT_STATUS.md 檔案，快速掌握目前專案的進度、現有檔案與上次留下的下一步任務。讀取完後，請用繁體中文簡短向我回報目前進度，並詢問我今天想從哪一個任務繼續開始。

AI 協同開發最高準則：先自動測試、確認通過後才回報展示

優質的 AI 助手不應只寫好程式碼就丟給學生碰運氣。AI 應在背後自動進行語法檢查與冒煙測試 (Smoke Test)，確認無報錯、無缺套件、相機可正常釋放後，才向使用者回報實測數據（如延遲 ms 與 FPS）並展示功能！

03 工程除錯實錄：初學者四大入門障礙與底層解方

寫程式不難，難在跨越作業系統的坑。這些真實發生的阻礙是絕佳的軟體工程素養教材。

障礙一：Windows Session 0 隔離

現象：AI 在後台啟動成功，但桌面完全看不到視窗！

AI 運行的終端屬於「背景服務程序 (Daemon)」，Windows 基於資安防護，嚴禁任何背景服務將視窗投射到使用者的實體螢幕 (Session 1)。

✅ 核心解法：GUI 視窗必須由使用者在前景實體終端輸入指令，或由桌面 Shell 雙擊啟動。

障礙二：雲端硬碟 UNC 虛擬路徑

現象：雙擊批次檔，命令視窗閃退並提示不支援 UNC 路徑

專案位於 Google 雲端硬碟等虛擬掛載磁區，傳統 CMD 的 cd /d 會因為無法識別虛擬 UNC 路徑而直接中斷。

✅ 核心解法：改用 pushd "%~dp0"，Windows 會自動指派暫時虛擬代號平穩切入目錄。

障礙三：Big5 與 UTF-8 編碼衝突

現象：批次檔閃退，出現「'ho.' 不是內部或外部命令」

繁中 Windows 的 CMD 預設使用 Big5 (代碼頁 950)，以 Big5 解譯 UTF-8 的中文字元會拆解出怪異指令符號，引發語法崩潰。

✅ 核心解法：啟動用 .bat 腳本一律保持 100% 純 ASCII 英文，不得夾雜任何中文。

障礙四：GUI 初次渲染尺寸死鎖

現象：視窗順利彈出，但畫面全黑，停留在啟動中

程式判定 if lbl_w > 100: 才畫圖，但 Tkinter 標籤初次寬度為 1，因此永遠不塞圖，標籤也永遠長不大，形成競態死鎖。

✅ 核心解法：加入容錯保底機制，未量測出尺寸時預設給予 720x405 畫布直接渲染第一幀。
