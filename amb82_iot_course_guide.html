2認識 AMB82-Mini

AMB82-Mini 用的是 Realtek RTL8735B，和一般 Arduino 板最大的差別是：它自己就有鏡頭、麥克風、WiFi 和影像壓縮能力，還有一顆專門跑 AI 的 NPU。所以不必接電腦、不必外掛攝影機模組，板子自己就能把影像變成網路上的串流或檔案。

項目內容課堂上會用到的地方
鏡頭500 萬畫素，可輸出 JPEG 或 H.264；常用 1920×1080、1280×720全部單元
影像通道通道 0：1920×1080 H.264；通道 1：1280×720 H.264；通道 2：1280×720 MJPEG第 2、5 節挑通道
儲存microSD 卡（FAT32）第 1、5 節
網路WiFi，可當連線端（STA）或自己開基地台（AP）第 2～6 節
LED程式裡寫 LED_B（藍）、LED_G（綠）當成「程式跑到哪裡」的指示燈
按鈕程式裡寫 PUSH_BTN，按下時是低電位第 5 節觸發錄影
AI 能力內建 NPU，可跑物件偵測、人臉辨識等模型課後延伸

3課前準備

這三件事請在研習前一天完成 開發板套件約 2 GB，三十個人在教室同時下載會塞爆網路，當天一定來不及。

1. 安裝 Arduino IDE 與開發板套件

  1. 到 arduino.cc 下載安裝 Arduino IDE 2.x。
  2. 開啟 IDE → 檔案 → 偏好設定 → 額外的開發板管理員網址，貼上： 
    https://github.com/ambiot/ambpro2_arduino/raw/main/Arduino_package/package_realtek_amebapro2_index.json
  3. 工具 → 開發板 → 開發板管理員 → 搜尋 AmebaPro2 → 安裝（下載時間長，請耐心等）。
  4. 安裝完成後，工具 → 開發板 → AMB82-MINI。

2. 確認電腦看得到板子

  1. 用可以傳資料的 USB 線接上板子（很多充電線只有電源，不能傳資料）。
  2. 工具 → 連接埠，要看到一個新的 COM 埠。看不到就先裝 USB 驅動程式（依講師說明）。
  3. 序列埠監控視窗右下角設 115200。

3. 其他準備

  • microSD 卡格式化成 FAT32（32 GB 以下最穩），插好再開機。
  • 要做 TFT 的人：不需要另外安裝程式庫，開發板套件已內建 ILI9341 函式庫（AmebaILI9341）。請準備 ILI9341 介面的 TFT 模組。
  • 電腦安裝 VLC（第 2 節播串流用）。
  • Google 帳號登入好（第 4 節）；手機安裝 Telegram（第 6 節）。
  • 下載本講義的程式包並解壓縮。
  • 準備一支手機熱點：學校 WiFi 常常隔離裝置，熱點是最有效的備援。

BlocklyDuino F2 與程式碼的關係

BlocklyDuino F2 是用積木寫 Arduino 程式的環境，拉完積木會產生對應的程式碼。課堂上用積木比較快，但看得懂程式碼才改得動。本講義每一節都附「積木在做什麼」與「對應的程式碼」，兩邊對照著看。積木包的版本以講師提供的為準。

4第 1 節：平台建置與第一支程式（09:20～10:10）

這節做出什麼

讓板子亮燈、在序列埠說話，然後拍一張照片存進 SD 卡。做到這裡，代表環境、鏡頭、SD 卡三件事都正常，後面五節才有基礎。

步驟 A：讓板子亮燈（確認能上傳程式）

  1. 工具 → 開發板選 AMB82-MINI；工具 → 連接埠選那個 COM 埠。
  2. 貼上下面的程式，按上傳（→ 箭頭）。
  3. 上傳完成後，板子上的藍燈會一秒亮一秒暗。
void setup() {
  Serial.begin(115200);
  pinMode(LED_B, OUTPUT);       // LED_B 是板子上的藍燈
}

void loop() {
  digitalWrite(LED_B, HIGH);
  Serial.println("亮");
  delay(1000);
  digitalWrite(LED_B, LOW);
  Serial.println("暗");
  delay(1000);
}
積木對照 BlocklyDuino F2 裡就是「設定腳位 LED_B 為輸出」＋「重複執行：數位寫入 HIGH → 等待 1 秒 → 數位寫入 LOW → 等待 1 秒」。拉完積木按「產生程式碼」，就會看到和上面幾乎一樣的內容。

步驟 B：拍一張照片存 SD 卡

  1. 關掉序列埠監控視窗（上傳時開著容易失敗），插好 SD 卡。
  2. 開啟程式包的 01_camera_snapshot/01_camera_snapshot.ino，直接上傳。
  3. 上傳後打開序列埠監控視窗（115200），會看到每 5 秒一行訊息。
  4. 拍 10 張後拔下 SD 卡，插到電腦看 img001.jpg～img010.jpg。

程式的三個重點：

VideoSetting config(VIDEO_FHD, CAM_FPS, VIDEO_JPEG, 1);  // 1920x1080、JPEG 格式
Camera.configVideoChannel(CHANNEL, config);              // 設定鏡頭
Camera.videoInit();
Camera.channelBegin(CHANNEL);                            // 開始輸出影像

fs.begin();                                              // 掛載 SD 卡
File file = fs.open(String(fs.getRootPath()) + "img001.jpg");
Camera.getImage(CHANNEL, &img_addr, &img_len);          // 取得最新一張 JPEG
file.write((uint8_t *)img_addr, img_len);                // 寫進檔案
file.close();
檢查點 序列埠出現「第 1 張：img001.jpg 大小 xx KB」，而且 SD 卡裡真的看得到照片。
常見錯誤原因與處理
看不到 COM 埠USB 線只能充電、驅動沒裝；換線、換孔，或依講師指示安裝驅動
上傳卡住不動序列埠監控視窗沒關；關掉再上傳。仍失敗就拔插 USB 重來
序列埠出現亂碼速率不是 115200
「讀不到 SD 卡」沒插到底、不是 FAT32、卡太大；先在電腦上格式化成 FAT32
照片全黑或過曝剛開機鏡頭還在自動調整，程式已等 2 秒；可把 delay(2000) 加大

動手改改看

  • 把 SHOT_INTERVAL 改成 1000，變成每秒一張的縮時素材。
  • 把 VIDEO_FHD 改成 VIDEO_HD，比較檔案大小差多少。
  • 加一個判斷：按下 PUSH_BTN 才拍照（提示語 ① 可以請 AI 幫忙改）。

5第 2 節：RTSP／RTP／TCP 影音串流（10:20～11:10）

這節做出什麼

板子連上 WiFi，把即時畫面用 RTSP 送出去，電腦用 VLC 打開就能看。

先搞懂三個名詞

名詞負責什麼生活比喻
RTSP控制：開始播、暫停、結束遙控器
RTP真正把影音一段一段送出去送貨的車
UDP送出去不確認有沒有收到，快但可能掉封包直接放在門口就走
TCP會確認、會重送，穩定但延遲較高要簽收，掉件會補寄

所以完整的說法是：用 RTSP 控制、由 RTP 傳送、底層走 UDP 或 TCP。畫面破格是掉封包（UDP 常見），畫面延遲越來越久則多半是網路塞住或快取設太大。

操作步驟

  1. 開啟 02_rtsp_stream/02_rtsp_stream.ino，把最上面的 ssid、pass 改成教室 WiFi。
  2. 上傳，打開序列埠監控視窗，等到出現 rtsp://192.168.x.x:554 這一行（板子藍燈會亮著）。
  3. 電腦開 VLC → 媒體 → 開啟網路串流 → 貼上網址 → 播放。
  4. 把手放到鏡頭前晃一晃，看畫面延遲大概多少。
延遲怎麼量 用手機開碼表對著鏡頭，再用手機拍「碼表＋電腦畫面」同框的照片，兩個時間相減就是延遲。VLC → 工具 → 偏好設定 → 輸入／編碼器 → 網路快取改成 200 毫秒，延遲會明顯下降。

比較實驗（可以寫進報告）

改哪裡怎麼改觀察
解析度#define CHANNEL 0（1080p）改成 1（720p）延遲、流暢度、畫質
位元率BITRATE 改成 1 Mbps 或 4 Mbps畫面破格的頻率
傳輸方式VLC 的網路串流選項勾選「RTP over RTSP (TCP)」破格變少但延遲變高
距離把板子拿遠離 AP訊號變差時的畫面變化

電腦端也可以用程式包的小工具，直接量到實際收到幾張畫面：

python tools/rtsp_check.py rtsp://192.168.1.50:554
python tools/rtsp_check.py rtsp://192.168.1.50:554 --tcp
檢查點 VLC 看得到即時畫面；序列埠的網址和 VLC 用的一致；知道自己的延遲大約幾秒。
常見錯誤原因與處理
序列埠一直印連線中WiFi 名稱或密碼錯、板子連不到 5GHz 專用網路；改用 2.4GHz 或手機熱點
VLC 轉圈圈打不開電腦和板子不在同一個網段（學校 WiFi 常隔離裝置）；兩台都連同一個手機熱點再試
畫面破格位元率太高或訊號差；BITRATE 調成 1 Mbps，或改用 TCP
延遲越來越久VLC 網路快取太大；改成 200 毫秒
很多人同時串流就變慢教室頻寬有限；輪流測，或降到 720p

6第 3 節：AP 模式網頁與 ngrok（11:20～12:10）

這節做出什麼

兩種「不必靠學校網路」的做法：AP 模式（板子自己當基地台，手機直接連）與 ngrok（把區網的服務開一個對外網址）。

步驟 A：AP 模式網頁

  1. 開啟 03_ap_web_snapshot/03_ap_web_snapshot.ino，把 ap_ssid 改成自己的（例如 AMB82-座號01），密碼至少 8 碼。
  2. 上傳後，序列埠會顯示網址（通常是 192.168.1.1）。
  3. 手機的 WiFi 清單連上剛剛設定的名稱，瀏覽器打開那個網址。
  4. 畫面會每 0.7 秒換一張照片，還可以按「開燈／關燈」。

網頁怎麼來的？板子就是一台小型網頁伺服器，收到不同網址回不同東西：

if (requestLine.indexOf("GET /photo") >= 0) {      // 要照片
    sendPhoto(client);                             // 回一張 JPEG
} else if (requestLine.indexOf("GET /led") >= 0) { // 要開關燈
    ledOn = (requestLine.indexOf("on=1") >= 0);
    digitalWrite(LED_B, ledOn ? HIGH : LOW);
} else {
    sendPage(client);                              // 回首頁 HTML
}

步驟 B：ngrok 讓校外也看得到

  1. 到 ngrok.com 註冊，下載 ngrok，執行 ngrok config add-authtoken 你的token（token 貼在自己的電腦上就好）。
  2. 板子改回連學校 WiFi（用第 2 節的程式，或把 AP 版改成連線模式），記下板子的 IP。
  3. 要分享網頁就開 ngrok http 192.168.1.50:80；要分享 RTSP 就開 ngrok tcp 192.168.1.50:554。
  4. 把畫面上出現的網址傳給別人；RTSP 的網址要改寫成 rtsp://0.tcp.ngrok.io:12345 這種形式再貼進 VLC。
ngrok 的限制與風險
  • 免費版每次重開網址都會變，上課中途重開，所有人的連結都會失效。
  • 免費版有連線數與流量限制，全班同時連很容易卡住。
  • 網址等於把教室畫面公開，知道網址的任何人都看得到：課後務必關閉（視窗按 Ctrl+C）。
  • 學校網路可能擋住 ngrok；擋住時就改用 AP 模式展示。
檢查點 手機連上板子的 AP 後看得到即時畫面，也能開關 LED；ngrok 網址在手機行動網路（關掉 WiFi）下也打得開。
常見錯誤原因與處理
手機連上 AP 卻打不開網頁手機可能因「沒有網際網路」自動切回行動網路；把該網路設成「保持連線」或關閉行動數據
畫面更新很慢板子一次只服務一個連線；請其他同學先關掉分頁
同學之間互相連錯板子AP 名稱重複；加上自己的座號
ngrok 顯示 ERR_NGROK_xxx多半是沒設定 authtoken，或免費版連線數用完

7第 4 節：雲端硬碟、試算表與 LINE（13:10～14:00）

這節做出什麼

板子拍照後自動上傳：照片存進 Google 雲端硬碟、資料寫進試算表、（選用）推播到 LINE。這是「把感測資料變成可以查、可以通知」的完整鏈路。

步驟 A：建立 Apps Script 接收端

  1. 打開 script.google.com → 新增專案，把程式包 04_cloud_upload/apps_script/Code.gs 的內容整份貼上（取代原本的 myFunction）。
  2. 按「部署」→「新增部署作業」→ 類型選 網頁應用程式。
  3. 執行身分：我；誰可以存取：任何人（這一步選錯，板子會一直失敗）。
  4. 第一次會要求授權，選自己的帳號 → 進階 → 前往「未經驗證的應用程式」→ 允許。
  5. 複製網址，長得像 https://script.google.com/macros/s/AKfycb.../exec。
  6. 先在瀏覽器打開這個網址，看到「AMB82 接收端運作中」代表部署成功。

不必等板子，電腦就能先測完整流程：

python tools/appscript_test.py https://script.google.com/macros/s/AKfycb..../exec

成功的話，雲端硬碟會出現 AMB82-Mini 資料夾與一張測試圖，並多一個「AMB82 上傳紀錄」試算表。

步驟 B：讓板子上傳

  1. 開啟 04_cloud_upload/04_cloud_upload.ino。
  2. 填入 WiFi 名稱密碼；scriptPath 只填網址的後半段，例如 /macros/s/AKfycb..../exec。
  3. deviceName 改成自己的座號，試算表才分得出是哪一台。
  4. 上傳並打開序列埠，成功時會看到 {"ok":true,...}。
為什麼要 Base64？ 照片是二進位資料，直接塞進網址或表單會壞掉，所以先用 Base64 編成純文字再傳，Apps Script 那端再解回來。代價是資料量變大約 1.33 倍，所以程式把解析度降成 768×768，上傳比較快。

步驟 C：推播到 LINE（選用）

LINE Notify 已經在 2025 年停止服務，現在要用 Messaging API：

  1. 到 developers.line.biz 建立 Messaging API channel，取得 Channel access token。
  2. 用手機加自己的官方帳號好友，取得自己的 userId。
  3. Apps Script → 專案設定 → 指令碼屬性，新增 LINE_TOKEN 與 LINE_TO 兩筆。
  4. 重新部署，再上傳一張照片，手機就會收到訊息與圖片。

LINE 只吃「公開的 HTTPS 圖片網址」，所以 Code.gs 會把檔案設成「知道連結的人可檢視」，再用雲端硬碟的縮圖網址推播。收到訊息卻沒有圖時，先把那個網址貼到無痕視窗，確認真的看得到圖。

檢查點 雲端硬碟有照片、試算表有一列（時間／裝置／檔名／連結／大小）、序列埠出現 "ok":true。
常見錯誤原因與處理
序列埠出現一堆 HTML 或 302部署權限不是「任何人」，或網址用到 /dev 結尾；重新部署並用 /exec
改了 Code.gs 卻沒效果Apps Script 要「重新部署」才會生效（管理部署作業 → 編輯 → 版本選新版本）
上傳很久或失敗照片太大；把 VideoSetting config(768, 768, ...) 調小，或降低上傳頻率
試算表沒有新列看 Apps Script 的「執行項目」記錄找錯誤訊息
LINE 沒收到token 或 userId 沒設；或官方帳號沒加好友
這一節牽涉到別人的臉 鏡頭會拍到教室裡的人，照片還會上傳到雲端。拍攝前先告知同學，示範時把鏡頭朝向桌面或物品；課後把雲端硬碟的照片刪掉，或把 Apps Script 部署改成「僅限自己」。

8第 5 節：MP4 錄影與 TFT 顯示（14:10～15:00）

這節做出什麼

按一下板子的按鈕開始錄影，錄滿設定的秒數自動存成 MP4；TFT 小螢幕顯示「READY／REC 幾秒／SAVED」與檔名。

步驟 A：先把錄影跑起來（不接螢幕也可以）

  1. 開啟 05_record_mp4_tft/05_record_mp4_tft.ino；沒有 TFT 就把 #define USE_TFT 1 改成 0。
  2. 插好 SD 卡，上傳，打開序列埠。
  3. 按下板子上的 PUSH_BTN，序列埠開始倒數，藍燈亮起。
  4. 錄滿 15 秒後出現「已存檔：class1.mp4」。把 SD 卡插到電腦，用播放器打開確認。

錄影的設定就這幾行，和 RTSP 的差別只在「輸出到哪裡」：

mp4.configVideo(config);              // 和鏡頭一樣的格式
mp4.setRecordingDuration(15);         // 錄幾秒
mp4.setRecordingFileCount(1);         // 錄幾個檔
mp4.setRecordingFileName("class1");   // 檔名（副檔名自動加 .mp4）
mp4.setRecordingDataType(STORAGE_VIDEO);   // 只錄影像；要收音改 STORAGE_ALL

videoStreamer.registerInput(Camera.getStream(CHANNEL));
videoStreamer.registerOutput(mp4);    // 第 2 節這裡接的是 rtsp
mp4.begin();

步驟 B：接上 TFT 顯示狀態

  1. 螢幕用 ILI9341 介面的模組，函式庫已內建在開發板套件裡，不必另外安裝。
  2. 接線：SCK → SPI_SCLK、SDI(MOSI) → SPI_MOSI、CS → SPI_SS、DC → 4 號腳、RESET → 5 號腳、VCC → 3V3、GND → GND、LED → 3V3。腳位不同就改程式最上面的 TFT_DC、TFT_RESET。
  3. 把 USE_TFT 改回 1，重新上傳。
  4. 顯示文字用 tft.setFontSize()、tft.setForeground()、tft.setCursor()、tft.println()。
不要用 Adafruit 的 ST7735 函式庫 那套函式庫相依的 Adafruit BusIO 在這塊板子上編譯不過（會出現 portOutputRegister was not declared）。請改用 ILI9341 模組與內建的 AmebaILI9341；本講義的程式已經驗證可以編譯。
TFT 顯示中文要另外處理 Adafruit 的字型只有英數字。要顯示中文，得先在電腦把文字轉成點陣圖再畫上去。課堂上先用英文與數字（REC、SAVED、檔名），課後想做中文版可以參考自行車後方來車專題的做法。
檢查點 SD 卡裡的 MP4 能在電腦播放；TFT 顯示狀態會跟著改變。
常見錯誤原因與處理
按了沒反應按鈕腳位不同；把 digitalRead(PUSH_BTN) == LOW 印出來確認
檔案打不開或長度 0錄影還沒結束就拔卡或斷電；等序列埠出現「已存檔」再動
錄第二段時失敗檔名重複；程式已自動編號，若自行修改請記得換名字
TFT 全白或全黑接線是否正確、背光（LED）腳是否接 3V3、DC／RESET 腳位是否和程式一致
編譯出現 portOutputRegister 錯誤用到了 Adafruit ST7735／BusIO；改用 ILI9341 與內建函式庫
想同時錄影又串流資源有限，建議二選一；要同時做請改用不同通道，並在課堂上實測

9第 6 節：Telegram Bot 遠端控制（15:10～16:00）

這節做出什麼

在手機 Telegram 傳指令，板子收到就動作：/photo 拍照傳回來、/led on、/led off 開關燈、/status 回報狀態。這是整天課的收尾——資料不只送出去，指令也能傳回來。

步驟 A：建立 Bot 並取得 chatID

  1. 手機 Telegram 搜尋 @BotFather → 傳 /newbot → 依指示命名，取得一串 Bot Token。
  2. 搜尋自己剛建立的 Bot，按「開始」，隨便傳一句話（例如 hi）。
  3. 電腦執行小工具，貼上 Token，它會列出你的 chatID： 
    python tools/telegram_check.py

步驟 B：上傳程式

  1. 開啟 06_telegram_bot/06_telegram_bot.ino，填 WiFi、botToken、ALLOWED_CHAT_ID。
  2. 上傳後，手機應該會收到「AMB82-Mini 上線了」。
  3. 傳 /photo，過幾秒就會收到剛拍的照片。

板子怎麼「收」訊息？它每兩秒主動問一次 Telegram：

GET /bot<TOKEN>/getUpdates?timeout=1&limit=1&offset=<上次的編號+1>

這叫做輪詢（polling）：板子沒有固定的對外網址，所以不是別人來找它，而是它定時去問。offset 的作用是「只要比上次新的訊息」，否則同一則指令會一直重複執行。

Token 就是密碼 拿到 Token 的人可以完全控制你的 Bot。不要上傳到 GitHub、不要貼在報告或簡報，截圖時要遮起來。程式裡的 ALLOWED_CHAT_ID 是第二道防線：別人就算找到你的 Bot，也無法叫板子拍照。
檢查點 /photo 收得到照片、/led on 會亮燈、/status 回報得出執行時間與訊號強度；用另一個帳號傳指令時，板子不會理他。
常見錯誤原因與處理
完全沒反應先用 tools/telegram_check.py 確認 Token 有效、chatID 正確
序列埠說連不上學校網路可能擋住 api.telegram.org；改用手機熱點
同一個指令一直重複執行offset 沒更新；確認 lastUpdateId 有被更新
照片送不出去照片太大；把解析度調小（程式預設 768×768）
別人也能操控ALLOWED_CHAT_ID 填錯；用小工具重新確認

動手改改看

  • 新增 /rec 指令：收到就錄一段 MP4（把第 5 節的程式合併進來）。
  • 新增「有人按按鈕就主動傳訊息給我」的功能（不必等指令）。
  • 把 /status 加上 SD 卡剩餘空間。

12安全、隱私與規範

  • 鏡頭會拍到人：練習時把鏡頭朝向桌面或物品；要拍到人之前先告知並取得同意。
  • 雲端照片會留下來：課後刪除雲端硬碟裡的照片，或把 Apps Script 部署改成「僅限自己」。
  • 金鑰不是程式的一部分：Bot Token、Apps Script 網址、LINE token 都等於密碼，不要放進報告、簡報、GitHub；截圖要遮。
  • 對外開放要收回：ngrok、AP 模式在課後都要關掉，不要讓教室畫面一直公開。
  • 不要監看他人：不可以把鏡頭裝在廁所、更衣室、宿舍，或用來監看特定同學，這會觸犯法律與校規。
  • 用電安全：板子與模組都用 3.3V／5V 低壓；接線前先拔掉 USB。
